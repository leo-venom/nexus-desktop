Como funciona

Uma frase entra.
Um jogo sai.

O NEXUS GAME não monta um projeto: ele escreve a página final. O shell cuida do contexto, da segurança e do ciclo de vida para o modelo entregar algo jogável no primeiro frame.

  1. Você descreve

    Prompt curto e, se quiser, uma imagem. Não existem modos separados: o pedido define o que a página é.

  2. O contexto é montado

    DIRECTIVE com 7 regras, tema BLACK CYBER, catálogo de 24 bibliotecas e o bloco da imagem quando existe.

  3. O modelo responde em SSE

    O endpoint OpenAI-compatible recebe o pedido pelo proxy local. A resposta chega em streaming, com prévia ao vivo.

  4. O HTML é validado

    Extração do documento, injeção das libs, polyfill de storage, checagem de sintaxe e reparos automáticos.

  5. O jogo abre no palco

    iframe sandbox, origem opaca, tela cheia já no primeiro frame, som futurista e HUD de 15px.

  6. Você refina e salva

    Edição cirúrgica devolve só os trechos alterados. Projetos ficam em salvos/<nome>/, com backup a cada save.

rode localmente 
# 1. clone o repositório
$ git clone https://github.com/leo-venom/nexus-desktop.git
$ cd nexus-desktop

# 2. instale o Electron (uma vez)
$ npm --prefix desktop install

# 3. abra o app
$ ./desktop/start.sh

Fallback sem Electron: python3 serve.py e abra http://127.0.0.1:8790/.

Imagens

A imagem entra no jogo.
Não no lugar dele.

Anexe pelo clipe dentro do prompt. Com um jogo aberto, o NEXUS GAME trata a imagem como asset real: fundo por padrão, textura quando você pede. Sem jogo aberto, ela vira referência para uma página nova.

02 / TEXTURA PEDIDA

Textura do objeto

Nomeie o componente — cubo, peça, nave, parede, chão. Em 2D o app usa createPattern/drawImage; em 3D, TextureLoader + material.map. A imagem não troca o fundo por engano.

material.map = new THREE.TextureLoader().load(path)

O caminho da imagem

  1. 01 Validação local por magic bytes: PNG, JPEG ou WEBP, até 12 MB, 40 MP e 10.000 px por lado.
  2. 02 Upload local POST /_api/ref-image gera imagens/nexus-ref-* com nome único, limite de 6 MB e modo 0600.
  3. 03 O prompt recebe o caminho exato e a regra de uso: fundo ou textura do componente nomeado.
  4. 04 Depois da geração, o app confere caminho + pista de uso. Se faltar, faz uma rodada de correção.
  5. 05 Ao salvar, o asset é copiado para assets/images/ e o projeto reabre offline.
Automático · padrão

Os pixels originais vão ao endpoint para máxima fidelidade. Se o provedor recusar imagem, o app cai uma vez para o relatório técnico local, sem perder a geração.

Somente local

O modelo recebe apenas dimensões, paleta e relatório de análise. Os pixels nunca saem do navegador.

Sem jogo aberto: a imagem volta ao fluxo de recriação — vira referência para uma página nova. Para recriar com um jogo aberto, reinicie a sessão (↺).

O que já está dentro

Ferramentas de estúdio,
sem a fricção de um estúdio.

Um shell completo ao redor do modelo: seleção de bibliotecas, edição, salvamento, som, desempenho e proteção. Você foca na ideia; o NEXUS cuida da engenharia.

Jogo no primeiro frame

Sem splash, menu ou botão iniciar. O objeto controlável já responde, com render síncrono antes do loop e controles de teclado/mouse.

Edição cirúrgica

Um novo comando devolve só os trechos alterados em JSON find/replace. O resto da página fica intacto, com fallback seguro para documento completo.

24 bibliotecas

Three.js r160 local, Babylon, Phaser, PixiJS, Matter, GSAP, Howler, Tone, ZzFX e mais. Loaders sob demanda para Rapier, Recast, postprocessing e BVH.

22 materiais + 28 shaders

Materiais PBR procedurais com normal map, roughness e metalness. Shaders GLSL para fogo, água, aurora, plasma, CRT, holograma e escudo.

Sessão com orçamento

1M de tokens por sessão, VU meter de 20 barras, KB ao vivo e tokens estimados durante a geração, exatos ao final.

Salvar, abrir, voltar

API REST local em salvos/<nome>/, assets copiados junto, backup automático a cada save e restauração pela interface.

Segurança

O jogo roda isolado.
O shell fica protegido.

Cada página gerada executa em um iframe com origem opaca. Ela não alcança o DOM do app, o localStorage nem a sua API key. A ponte com o shell é um postMessage com whitelist.

  • iframe sandbox="allow-scripts" sem allow-same-origin: a página gerada não tem a origem do app.
  • Electron carrega apenas 127.0.0.1, com contextIsolation, sandbox e sem nodeIntegration.
  • Proxy /_proxy bloqueia redes privadas, link-local e metadata de nuvem, fixa DNS validado e revalida redirecionamentos.
  • Imagem validada por magic bytes, 6 MB, nome único e modo 0600. Nada do arquivo é executado.
  • Links externos abrem em janela isolada; protocolos desconhecidos são bloqueados.
